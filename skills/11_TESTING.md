# 11 - Testing

**Purpose:** Define the minimum evidence needed to gain confidence.

**Confidence note:** No test suites or tooling are present.

Test:
- Google Sign-In success, failure, cancellation, and account-linking cases.
- Every user level against every MVP feature.
- Direct API access for unauthorized and cross-resource requests.
- Input validation and injection surfaces.
- Location removal, retention expiry, deletion, export, and aggregation thresholds.
- Consent denial and prohibited resale flows.
- Web and Android parity for authentication and role restrictions.

Add a framework only after source manifests exist. Coverage percentages cannot be claimed from document count or placeholder code.
